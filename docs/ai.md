# AI bot

API キーを入れたとき（ローカル AI は、選んだとき）だけ動きます。キーがなければ、どこにも通信しません。

- **AI のおすすめ**: 起動したときに、選んでいるサービスの API キーがなければ「AI で楽々タスク管理」のダイアログが出ます。「AI bot を開く」で右にチャットが開き、「API キーを設定」から設定に進めます。「ローカル AI を使う」で、サービスをローカル AI にしてチャットを開きます（手元のサーバーを探し、最初のモデルを使います）。「今後は表示しない」に印を付けると、次の起動から出ません（設定 `ai.promo.hidden`）。ロック中は、解除してから出ます

- **bot**: bot はいくつでも作れます（30 個まで）。bot ごとに、名前・インストラクション（口調や役割など、その bot がいつも従う指示。8,000 文字まで）・アイコン・色・動きを持ちます。上のバーの bot の名前を押すと、bot を選ぶメニューが開きます。会話は bot ごとに分かれ、話している bot を変えると、その bot のいちばん新しい会話が開きます（なければ新しい会話）。並列の会話も、同じ bot が答えます
  - 「bot を追加」で「新しい bot」が足され、その場で名前を書けます。「bot を編集」か、歯車で開く「設定」の「AI」→「bot」で、行を押して開くと、インストラクション・アイコン（ワークスペースと同じアイコンと色。追加した画像も使えます）・動きを変えられます。最後の 1 つは消せません
  - **動き**: なし・ふわふわ・ぴょんぴょん・ゆらゆら・くるくる・どきどき から選びます。bot が考えている間と、会話が空のときに動きます。画像のアイコンは、ふわふわとぴょんぴょんだけ動きます
  - **覚えたこと**: 会話で分かったユーザーの好みや直されたことを、bot が自分で覚えます（`remember_for_bot`。bot ごとに 4,000 文字まで、超えたら古いものから消えます）。覚えたことは、その bot と話すたびにメッセージの最後に添えます。開いた bot の「覚えたこと」の × で消せます。チャットで「〜は忘れて」と頼むこともできます（`forget_for_bot`）
  - インストラクションは最初の指示に入れ、覚えたことはメッセージの最後に添えるので、覚えても最初の指示は変わりません。新しいタスクを整える・コメントからの更新・定期チェックのような自動の処理は、bot ではなくアプリとして動きます
  - **ほかの bot に渡す**: 「秘書に頼んで」のように言うと、今の bot がほかの bot に仕事を渡します（`hand_off_to_bot`）。渡した先の bot が並列の会話で動き、入力欄の上に「bot の名前: 頼んだこと」で出て、終わると会話の一覧に残ります。並列の会話から、さらにほかの bot には渡せません
  - チャットで頼んで、bot を足す・変える・消すこともできます（`list_ai_bots` / `create_ai_bot` / `update_ai_bot` / `delete_ai_bot` / `set_bot_icon`）。bot の変更は `Ctrl/⌘ + Z` で戻せ、エクスポートにも入ります（`data/ai_bots.json`）
- **対応するサービス**: Claude（Anthropic API）、ChatGPT（OpenAI API）、OpenCode、OpenCode Go、Cursor（Cursor の CLI `agent` を使います）、ローカル AI（下）。モデルと考える深さ（effort）は歯車で開く「設定」の「モデル」か、チャットの「設定」で選べます。考える深さはモデルごとに覚え、モデルを切り替えるとそのモデルで前に選んだ深さに戻ります（例: Claude Fable 5.2 は low、Claude Opus 5.5 は high）
- **ローカル AI**: 手元（か同じネットワーク）で動かす AI のサーバーを使います。インターネットにつながっていなくても動きます
  - **対応するサーバー**: Ollama（Ollama の API `/api/chat`）と、OpenAI 互換の API（`/v1/chat/completions`）を持つサーバー。LM Studio、llama.cpp（`llama-server`）、vLLM、LocalAI、Jan、KoboldCpp、text-generation-webui、GPT4All などです
  - **自動で探す**: 設定の「サーバー」の URL が空なら、手元（127.0.0.1）の各サーバーの最初のポート（Ollama 11434、LM Studio 1234、llama.cpp 8080 と 9931、vLLM 8000、Jan 1337、KoboldCpp 5001、text-generation-webui 5000、GPT4All 4891）を探し、最初に見つけたものを使います。見つけたサーバーは URL の下に並び、押すとそのサーバーにします。別の PC のサーバーは URL（`http://192.168.1.10:11434` など。`/v1` は付けても付けなくてもかまいません）を入れて Enter で使います。URL を空にすると、また自動で探します。どの種類のサーバーかは、答え方で見分けます（Ollama は `/api/version`、LM Studio は `/api/v1/models`、ほかは `/v1/models`）
  - **API キー**: なくても使えます。キーが要るサーバー（Jan など）には、設定の「API キー」に入れたキー（か環境変数 `LOCAL_AI_API_KEY`）を `Authorization: Bearer` で付けます
  - **モデル**: サーバーに入っているモデルを一覧から選びます（Ollama は `/api/tags`、LM Studio は `/api/v1/models`、ほかは `/v1/models`）。一覧は開くたびに読み直すので、あとから入れたモデルも出ます。モデルを選んでいなければ、一覧の最初のモデルを使います。文の埋め込み用のモデルは出しません
  - **できること**: Ollama（`/api/show`）と LM Studio はモデルごとにツールと画像を使えるかを答えるので、モデルの一覧の名前の横に印（レンチはツール、絵は画像）を出します。行にマウスを乗せると、ID と使えるものが出ます。答えないサーバー（llama.cpp、vLLM など）には、まずツールや画像を送り、モデルやサーバーが断ったら（Ollama の「does not support tools」、llama.cpp の `--jinja` や `mmproj`、vLLM の `--enable-auto-tool-choice` など）外して送り直し、モデルごとに覚えます（アプリを起動し直すと、また送ってみます）
  - **ツールを使えないモデル**: ツールなしで会話します。チャットに「〜はツールを使えないので、アプリを操作せずに答えます」と 1 回出し、AI には操作の手順を伝えるよう頼みます。新しいタスクを整える、コメントから進捗を更新する、GitHub の定期チェック、定期実行と定時タスクはツールで結果を書くので、ツールを使えないモデルでは送らずに失敗として残ります
  - **添えたファイル**: 画像は、画像を読めるモデルにだけ渡します。PDF と、画像を読めないモデルへの画像は、置いた場所だけを伝えます（文字にできるファイルは、ほかのサービスと同じく文字にして渡します）
  - **考える深さ**: サーバーが選べると答えた深さだけを選べます（Ollama は `/api/show` の `thinking`、LM Studio は `reasoning`）。Ollama には `think`、ほかには `reasoning_effort` で送ります。「標準」はモデルの標準のままです
  - **一度に読む長さ**: Ollama は標準の長さがツールの説明より短く、超えた分を黙って切るので、送る分が入る長さ（`num_ctx`）を 8,192 トークンごとに選んで付けます（モデルの上限は超えません）。ほかのサーバーの長さは、サーバーでモデルを読み込むときの設定のままです
  - **キャッシュとストリーミング**: 手元のサーバーは同じ頭の部分を自分で使い回すので、キャッシュの指定は送りません。返事はほかのサービスと同じく、できあがってから出ます
- **プロンプトキャッシュ**: Claude と OpenCode の Messages API には、どのリクエスト（チャット、並列の会話、新しいタスクを整える、コメントからの更新、GitHub の定期チェック、定期実行と定時タスク）にもキャッシュの区切り（`cache_control`）を付けます。区切りはツールの最後、最初の指示の最後、最後のメッセージの 3 か所です。ツールと最初の指示は会話をまたいで同じなので、Claude では 1 時間残し、会話の分は 5 分です（OpenCode は標準の 5 分だけ）。日付や今の画面は最初の指示に入れず、メッセージの最後に添えるので、前の部分は変わりません。効いているかは、Claude Console のプロンプトキャッシュの使用状況か、`ANTHROPIC_API_KEY` を付けた `mise run cache-check`（本物の API に 2 回送って、2 回目がキャッシュを読むことを確かめます）で見られます。ChatGPT と OpenCode の Chat Completions は、サービスの側で同じ頭の部分を自動でキャッシュします
- **API キー**: OS のキーチェーン（macOS のキーチェーン、Windows の資格情報マネージャー、Linux の Secret Service）に保存します。データベースにもエクスポートの zip にも入りません。環境変数（`ANTHROPIC_API_KEY`・`OPENAI_API_KEY`・`OPENCODE_API_KEY`・`CURSOR_API_KEY`・`LOCAL_AI_API_KEY`）でも渡せます
- **アプリの操作**: アプリでできる操作は、どれもチャットで頼めます。タスク・コメント・添付・完了チケット・ワークスペース（名前、アイコン、設定）・担当者の読み書き、画面（開く場所、タスクを開く、一覧の絞り込みと並び順、表の列、左のメニュー・詳細・チャット・シェル、ペイン、ダイアログ、新しいウィンドウ、ターミナル）、カスタマイズ（テーマの適用・保存・名前の変更・削除、レイアウト、ライトとダーク、背景の画像、透明度、ぼかし、カード、浮いたパネル、密度、期限の表示、ホバー、書体の優先順、色）、AI の設定、ロック（自動でロックするまでの時間、ロック中の通知も）、リマインダー、自動アップデート、エクスポートとインポート、元に戻す・やり直しです。AI の変更は、ツールの呼び出し 1 回ずつ `Ctrl/⌘ + Z` で元に戻せます。削除、インポート、上書きになるエクスポート、オート実行をオンにすることは、実行の前に確認が出ます。確認は「許可」「このチャットでは常に許可」「拒否」から選びます。「このチャットでは常に許可」を選ぶと、同じ種類の操作（たとえばタスクの削除、シェルのコマンド）は、その会話の間は確認なしで実行します。新しい会話にすると、また確認が出ます。API キーはチャットに書かず、「設定」で入れます
- **GitHub のリンク**: メッセージに GitHub のリンク（issue、プルリクエスト、ファイル、コミット、リポジトリ）を書くと、`gh` コマンドで中身を取ってきて AI に渡します。`gh` がなければ、公開されているものを GitHub の API から取ります
- **Slack のリンク**: メッセージに Slack のメッセージへのリンク（`https://〜.slack.com/archives/…`）を書くと、[Slack CLI](https://docs.slack.dev/tools/slack-cli/) の `api conversations.replies` で、そのメッセージとスレッドの返信（100 件まで）を取ってきて AI に渡します。トークンは Slack CLI が環境変数 `SLACK_USER_TOKEN` から読み、このアプリは保存しません。呼ぶコマンドは `slack-cli` です。macOS と WSL の中では、`slack-cli` がなければ `slack` を呼びます。macOS と Linux ではログインシェルの設定（PATH と環境変数）を読み、Windows では `slack-cli` がなければ WSL の中のものを呼びます
- **GitHub のアカウント**: `gh` にログインしているアカウントを起動のときに読み、AI に伝えます（入力は要りません）。`gh` の設定を読むだけで、設定に名前がなく API キーがあるときだけ `gh api user` で GitHub に聞きます。Windows では、WSL の中の `gh` も読みます。チャットの「設定」に今のアカウントが出て、横のボタンで読み直せます
- **GitHub の定期チェック**（標準はオン。API キーがなければ動きません）: 未完了のタスクに書かれた issue とプルリクエストのリンク（1 回に 50 件まで。最近書き換えたタスクのものから）を、`gh` で 24 時間に 1 回見に行きます。間隔は「設定」で 1 時間〜24 時間から選べます。最後にチェックした時刻から数えるので、アプリを起動し直しても数え直しにはなりません。前回のチェックからの進展（コメント、レビュー、コードへのコメント、コミット、クローズやマージ）があったときだけ AI を呼び、AI がそのタスクにコメントで要約を書きます。自分の動きは `gh` にログインしているアカウントで見分け、「自分」として AI に渡します。進展がなければ AI を呼ばず、何も書きません。アプリをロックしている間も動きます。AI への指示は書き換えられます。定期チェックからは、タスクの削除とコマンドの実行は行いません。覚えておくのは、リンクごとのいちばん新しい動きの時刻と状態だけです
- **定期実行**: 繰り返しのタスクに「AI への指示」を書いておくと、次の回を作ったときに AI がその指示を実行し、結果をその回のタスクにコメントします（例: 週次の報告の下書き）。API キーがなければ通信せず、失敗として残り、やり直せます。アプリをロックしている間も動きます。ここからは、タスクの削除とコマンドの実行は行いません（[docs/repeat.md](repeat.md)）。ワークスペースの[定時タスク](schedule.md)の「AI への指示」も同じように、作ったタスクで実行します
- **新しいタスクを整える**（標準はオン。API キーがなければ動きません）: タスクを作るか、タスクに新しい GitHub か Slack のリンクを書くと、AI がリンクを読んで、タイトルと説明を整えます。整えている間は、タスクの行と上のバーの AI ボタンで印が回ります。ここからは、タスクの削除とコマンドの実行は行いません。「設定」でオフにできます
- **コメントから進捗を更新する**（標準はオン。API キーがなければ動きません）: タスクにコメントを書くか書き直すと、3 秒待ってから AI がコメントを読み、進捗・状態・期限・開始日・優先度を更新します。タイトルと説明は変えません。詳細の「進捗」の横のボタンで、AI が変えたところを元に戻せます。進捗は一覧にも棒と数字で出ます。「設定」でオフにできます
- **ルール**: AI がいつも従う指示を、名前を付けていくつでも置けます（1 つの場所に 50 個まで、1 つ 4000 文字まで）。歯車で開く「設定」の「AI」→「ルール」で、「＋」を押すと「新規ルール」が足され、その場で名前を書けます。行を押すと開いて本文を書け、ほかの場所を押すと保存します。Esc で書きかけを捨てて閉じます。スイッチで使う・使わないを切り替え、「いつも」「チャット」「自動の処理」で使う場面を選べます（自動の処理は、新しいタスクを整える、コメントから進捗を更新する、GitHub の定期チェック）。ルールの変更は `Ctrl/⌘ + Z` で戻せ、エクスポートにも入ります
  - **グローバルとワークスペース**: 上のボタンで「すべてのワークスペース」か、ワークスペースを選びます。ワークスペースのルールは、そのワークスペースとサブワークスペースで使います。チャットでは今開いているワークスペースの、自動の処理では扱うタスクのワークスペースのルールを使います。ワークスペースの右クリックの「AI のルール」と、ワークスペースの設定の「AI のルール」からも開けます
  - グローバルのルールは最初の指示に入れ、ワークスペースのルールはメッセージの最後に添えます
  - チャットで「これからは〜して」のように頼むと、AI がルールにします（`list_ai_rules` / `create_ai_rule` / `update_ai_rule` / `delete_ai_rule`）
  - 前の版の「いつも AI に伝えること」とワークスペースの「AI に伝えること」は、それぞれ最初のルールになります
- **ファイルを添える**: 入力欄の左のクリップのボタンで選ぶか、チャットにドロップするか、入力欄に貼り付けると（コピーした画像、エクスプローラーや Finder でコピーしたファイル）、ファイルを添えて送れます（1 回に 20 件まで）。種類は拡張子ではなく中身で見分けます
  - 画像（PNG・JPEG・GIF・WebP）と PDF は、そのまま AI に渡します。BMP・TIFF・ICO は PNG か JPEG にし、長い辺が 2,576 px を超える画像や 3.7 MB を超える画像は縮めて渡します
  - テキスト（UTF-8・UTF-16・Shift_JIS・EUC-JP）と、Word（docx）・Excel（xlsx）・PowerPoint（pptx）・OpenDocument（odt・ods・odp）は、文字を取り出して渡します（1 ファイル 100,000 文字まで。超えた分はファイルのパスを伝えます）
  - ほかの形式（音声、動画、HEIC、古い Office の形式、圧縮ファイルなど）は、名前・種類・大きさ・置いた場所を伝え、AI がシェルのコマンドで読めるようにします（zip は入っているファイルの一覧も渡します）。どの形式でも、置いた場所は AI に伝えます
  - Claude には画像・PDF・文書のブロックとして、ChatGPT・OpenCode には画像とファイルの入力として渡します。Cursor の CLI には画像や PDF を渡せないので、置いた場所を伝えて CLI に読ませます
  - 1 回のリクエストに入れる画像と PDF は、新しいものから合計 20 MB・50 件までです。それより前に添えたものは、置いた場所だけを伝えます
  - 送ったファイルは会話に出て、押すとほかのアプリで開きます
- **会話の一覧**: 会話は 30 件まで残り、チャットの上の時計のボタンから開き直せます。タスクの詳細の AI のボタンで、そのタスクについての会話を開けます
- **自動の実行**: タスクの整理やコメントからの更新は会話に混ぜず、動いている間だけ入力欄の上に出ます。失敗は消すまで赤く残り、やり直せます。結果はタスクの「AI の記録」と、メニューの「AI の実行履歴」（50 件まで）に残ります
- **考え中に送る**: 答えを待っている間も送れます。AI が今の会話の続きか別の依頼かを決め、続きは答え終わってから同じ会話に、別の依頼は並列の会話（同時に 3 つまで）で動かします。並列の会話は終わると入力欄の上から開けて、会話の一覧にも残ります。振り分けに使うモデルは設定の「振り分けのモデル」で選べ、選ばなければ今のモデルを使います。並列の会話では、削除やコマンドのような確認が要る操作はしません
- AI には、今見ている画面（ワークスペース、一覧に出ているタスク、開いているタスク、選んでいるタスク）も伝えます
- **シェル**: チャットの横のターミナルです。AI がコマンドを実行するときは、先に確認が出ます。入力行に自分でコマンドを打つこともできます（`cd` で移動、↑↓ で履歴）。色はコマンドの出力どおりに出て、長い行は幅で折り返します。出力はドラッグで選び、`Ctrl + C`（macOS は `⌘ + C`）か `Ctrl + Shift + C` でコピーします。選んでいないときの `Ctrl + C` は実行中のコマンドを子プロセスごと止め、`Ctrl + L` で画面をクリアします。`vim` や `claude` のように画面全体を使うコマンドは、同じ場所の「＋」で開く[ターミナル](terminal.md)で動かせます
- **コマンドが動くシェル**: AI のコマンドは、今見ているタブのシェルで動きます。[ターミナル](terminal.md)のタブ（WSL の Ubuntu など）を見ていればそのシェル、「AI」のタブならタブの名前に出ているシェルです。「AI」のタブのシェルは「設定」の「動作」の「AI のタブのシェル」で選べ、選んでいなければ Windows は PowerShell（PowerShell 7 がなければ Windows PowerShell）、macOS と Linux は bash です。どのシェルかはメッセージごとに AI に伝え、確認の文にも出ます。出力は「AI」のタブに出ます
- **PATH**: Windows では、コマンドを動かすたびにシステムとユーザーの PATH を読み直します。アプリを起動したあとに入れたコマンド（`slack-cli` など）も、アプリを開き直さずに見つかります
- **オート実行**（標準はオフ）: 「設定」でオンにすると、コマンドの実行とタスクの削除を確認なしで行います。オンの間は、チャットの上に「オート実行」と出ます。定期チェックには適用されません
- **ウィンドウ**: チャットもシェルも別ウィンドウに切り離せ、元の場所に戻せます
- **ディスク**: シェルの出力はメモリの中だけに置き、ディスクには書きません。シェルの表示は 4,000 行まで、AI に渡す出力は 20,000 文字までです
- **添えたファイルの置き場所**: データベースの隣の `ai-files` に、内容ごとに 1 つだけ写して置きます（同じファイルを何度添えても増えません。画像は縮めたものを置きます）。20 MB を超えるファイルは写さず、元の場所を AI に伝えます。どの会話からも使われなくなったものは、起動したとき・会話を消したとき・古い会話が一覧からあふれたときに消し、合計が 200 MB を超えたら、使っていない古いものから消します。消えたファイルは、会話には名前だけが残ります
