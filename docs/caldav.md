# CalDAV との同期

右上の歯車で開く「設定」の「連携と同期」の「連携」でアカウントを足し、サーバーのカレンダーをワークスペースにつないだときだけ動きます。標準ではどこにもつながりません。macOS の「リマインダー」アプリとの同期も、同じ「連携を追加」から選びます（[reminders.md](reminders.md)）。ほかのツールからの取り込みも、ここから選びます（[import.md](import.md)）。

CalDAV のタスク（VTODO）を扱えるサーバーなら、どれとも同期できます（Nextcloud、Radicale、Baïkal、Synology Calendar、Fastmail など）。Google Tasks・Microsoft To Do・iCloud の新しい形式のリマインダーは CalDAV のタスクを出さないので、つなげません。そのため「連携を追加」の一覧にもありません。

## つなぎ方

1. 「連携と同期」の「連携を追加」を押し、プロバイダを選びます
   - **Fastmail**: サーバーは `https://caldav.fastmail.com/` に決まっているので、ユーザー名（メールアドレス）と、Fastmail の設定で作ったアプリパスワードだけを入れます
   - **Nextcloud**・**その他の CalDAV アカウント**: サーバーも入れます。`https://` は省けます。サーバーのトップ（`example.com`）でも、CalDAV の場所（`https://example.com/remote.php/dav/`）でもかまいません。`/.well-known/caldav` から自分のカレンダーの場所を探します
2. ユーザー名・パスワードを入れて「次へ」（Enter）を押します
   - 「説明」は一覧に出す名前です。省くと `ユーザー名@サーバー` で出ます
   - 2 段階認証のあるサービスでは、そのサービスで作ったアプリパスワードを使います
   - パスワードは OS のキーチェーン（macOS のキーチェーン、Windows の資格情報マネージャー、Linux の Secret Service）に入れます。このアプリのデータベースとエクスポートには入りません
   - 「キャンセル」か Esc で閉じると、調べている途中でもアカウントは足しません
3. タスクを入れられるカレンダーが並びます。最初は全部にチェックが付いています。同期しないものはチェックを外し、「追加」を押します
   - チェックしたカレンダーは、アカウントの名前（説明）のワークスペースの下に、カレンダーの名前のサブワークスペースを作ってつなぎます
4. 足したあとも、「連携と同期」の一覧のチェックボックスで、つなぐ・接続しないを切り替えられます
   - チェックを付けると、アカウントのワークスペースの下の、カレンダーと同じ名前でどこにもつないでいないサブワークスペースにつなぎます。なければ作ります（外して付け直すと、前のワークスペースに戻ります）
   - つないでいるカレンダーの右のメニューで、つなぐワークスペースを選び直せます。「新しいワークスペース」はアカウントのワークスペースの下に作り、「接続しない」は同期をやめます
   - 1 つのカレンダーにつなげるワークスペースは 1 つ、1 つのワークスペースにつなげるカレンダーも 1 つです
   - 鍵のアイコンのカレンダーは読み取りのみです。サーバーのタスクは入りますが、このアプリで変えたことは送れず、サーバーの内容に戻ります

つなぐとすぐに同期します。そのあとは、このアプリでタスクを変えると少し待ってから送り、サーバーは 1 分ごとに見に行きます。「今すぐ同期」の ↻ は、カレンダーの一覧も読み直します。

## 同期するもの

| このアプリ | CalDAV（VTODO） |
| --- | --- |
| タイトル | SUMMARY |
| 説明 | DESCRIPTION |
| URL | URL と、説明の末尾の URL だけの行（下を参照） |
| 状態（未着手・進行中・完了・中止） | STATUS（NEEDS-ACTION・IN-PROCESS・COMPLETED・CANCELLED） |
| 優先度 | PRIORITY |
| 進み具合 | PERCENT-COMPLETE |
| 予想工数 | ESTIMATED-DURATION（DURATION には月がないので、1 か月は 30 日で送ります） |
| 開始日・期限 | DTSTART・DUE（日付だけなら日付、時刻つきなら UTC で書きます） |
| カテゴリ | CATEGORIES |
| 親タスク | RELATED-TO（RELTYPE=PARENT） |
| 担当者と RACI | ATTENDEE（R は REQ-PARTICIPANT、A は CHAIR、C は OPT-PARTICIPANT、I は NON-PARTICIPANT。担当者ごとの完了は PARTSTAT=COMPLETED） |

- コメント・添付・変更履歴・繰り返し・AI の記録・所要時間の基準は、このアプリだけのものです。サーバーには送りません
- このアプリが扱わない項目（通知の VALARM、繰り返しの RRULE、`X-` で始まる項目など）は、サーバーにあったとおりに残して送り返します
- 担当者は、自分のアカウントの URI（メールアドレスなど）なら「自分」になります。知らない人は、そのワークスペースの担当者として足します。このアプリの担当者は `urn:uuid:` の URI で送ります
- 1 人に複数の役を付けているときは、R、A、C、I の順で最初の役を送ります。サーバーから同じ役が返ってきたときは、このアプリの複数の役をそのまま残します

### 説明の末尾の URL

サービスによっては、そのサービスのタスクの画面の URL を説明の末尾に足して返します。受け取った説明の末尾にある URL だけの行（空行で区切られたもの）は、本文から外してタスクの URL 欄（タイトルの下）に出します。送り返すときは、外した URL を元の位置に戻します。

- 本文を書き換えても、末尾の URL はそのまま残ります
- URL 欄で消した URL は、サーバーの説明からも消えます
- サーバーの URL 項目には、URL 欄の URL のうち説明の末尾から来たもの以外の最初の 1 つを送ります。2 つ目からは、このアプリだけに残ります

## 両方で変えたとき

項目ごとに、前の同期のあとでどちらが変えたかを見ます。片方だけが変えた項目はその内容に、両方が同じ項目を変えたときはサーバーの内容にして、何がそうなったかを画面に出します。このアプリで書いていた内容は、タスクの変更履歴に残っています。

- サーバーで消したタスクは、このアプリでも消します。ただし、このアプリで変えていたときは、サーバーに作り直します
- このアプリで消したタスクは、サーバーでも消します
- サーバーから受け取った変更は、このアプリの「元に戻す」の相手になりません
- 同期の間にこのアプリで変えたことは、上書きしません。次の同期で送ります

## つながらないとき

サーバーにつながらない間も、このアプリのタスクはそのまま使えます。つながったときに、たまっていた変更を送ります。失敗したときは、画面の上にエラーを出し、「連携と同期」のアカウントの行に ☁ の印を出します（乗せると理由が出ます）。

## 外すとき

- カレンダーのチェックを外すか、メニューで「接続しない」を選ぶと、同期をやめます。タスクとワークスペースは両方に残ります
- アカウントのごみ箱で「アカウントを外す」を選ぶと、アカウントとキーチェーンのパスワードを消します。タスクは両方に残ります
- つないだワークスペースを消すと、つながりだけが外れます。サーバーのタスクは消しません

## 書き出し

エクスポートの zip には、アカウント・カレンダーのつながり・同期の控えは入りません（パスワードはもともとこのアプリのデータベースにありません）。別の端末では、アカウントを足し直します（チェックしたカレンダーは新しいワークスペースにつながります）。取り込んだワークスペースにつなぐと、サーバーから来たタスクが二重になることがあります。
